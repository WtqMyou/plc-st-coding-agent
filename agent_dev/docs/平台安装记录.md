## 安装修复经过

初次 CODESYS 安装期间，主程序与组件管理器发生 DLL 文件占用，留下受损记录；普通 MSI 修复又出现组件记录与插件目录不一致。不能通过删除受损标记来当作安装成功。

已保留初次安装、修复、组件重装、官方卸载和重新安装日志。组件管理器重装 CFC 4.5、Application Composer 4.5、LD/FBD 4.7 后返回成功；随后使用官方卸载流程清理，卸载返回 0，再安装到新的 E 盘目录。Scripting 组件随匹配安装包安装，版本为 4.2.0.0。

重新安装使用安装器的 INSTALLDIR、CDS_SEPARATE_REPO、CDSFOLDERCAREPO 目录参数，并指定 E 盘下载缓存。安装器为独立仓库追加了标识后缀，因此复现时应读取实际日志，不能假定后缀在另一台机器相同。安装参数形式参考 [InstallShield 官方命令行文档](https://docs.revenera.com/installshield/helplibrary/IHelpSetup_EXECmdLine.htm)。

## 编译适配器

CODESYS 使用 `CODESYS V3.5 SP22 Patch 4` profile，Scripting 在带设备与 Application 的模板上插入 DUT 和 POU，强制链接生成代码。每次任务采用新的工程目录和随机 nonce；既检查进程退出状态，也检查当次脚本结果和编译错误，不能复用旧成功文件冒充结果。

模板的 Standard 库允许通常的未限定函数调用，例如 LEN、CONCAT、MID。通过后额外生成本地离线 `.app` 与编译信息；不执行下载操作。字符串适配采用 MID 取单字符字符串，并显式使用 UDINT 运算组装 IPv4 值。

`codesys_reference_batch.py` 在参考解审计时复用同一个 CODESYS 进程，逐工程生成带 nonce 的结果，并用外部监视器执行每题超时限制。此批处理耗时只用于参考解验收，不当作模型性能数据；正式 Agent 候选仍通过统一的独立编译接口运行。

OpenPLC 使用官方 CLI 创建完整工程，写入 POU、DUT 与调用程序，为 VAR_IN_OUT 提供调用方存储，然后编译到 Runtime v4。用户数据目录明确位于 E 盘。

两个适配器单次平台操作最多 120 秒，包括创建工程等子步骤；超时停止本次进程树，结果记 timeout。缺失工具、脚本异常和没有当次结果均单列，不能算通过。

## 在另一台机器复现

1. 从官方来源下载对应版本并核对 SHA256，安装到大容量盘；CODESYS 可能要求 Store 登录和 Windows 管理员确认，由接手者本人完成。
2. 保证匹配的 Scripting 组件可用。运行 codesys_probe.py 建立带 Application 的模板，核对 config.example.json 中本机路径，另存 config.local.json。
3. 运行 `scripts/native_controls.py`，必须同时得到正确程序 passed 和故意错误程序 failed。
4. 执行 `platform-check --adapted` 或 refresh_native_evidence，核对 35 题编译和全部 435 条输出断言。原契约结果单独保存，不能与适配版混报。
5. 交接包内 platform_projects 保存三类实际工程与关键日志；完整安装包、缓存和更多构建文件留在 E 盘，不塞入交接 ZIP。

文件清单及 dataset_freeze 中的哈希针对文件原始字节；候选 source_sha256/code_hash 针对 Python 读取并规范为 LF 换行的 UTF-8 源码文本。复核后者可使用 `hashlib.sha256(Path(path).read_text(encoding="utf-8").encode()).hexdigest()`。
