# 先读我 · stbench v1.2（2026-10-27）

> 一句话：这是一个**自研的 IEC 61131-3 结构化文本（ST）验证流水线**——把大模型写出的 ST 代码
> 依次送进「编译 → 类型检查 → 逐拍仿真 → LTL 有界模型检查」四层裁判，
> 附带 20 道公共题 + 15 道自建题的数据集、全部参考解、Agent 回路与实验脚本。

---

cd stbench

> Windows 必读：**所有**中文输出命令都要带 `-X utf8`，否则控制台是乱码（不是程序错）。

## 4. 已知边界（如实说明，答辩也会问）

1. **没有在真实 PLC / CODESYS 上编译过。** 编译器与仿真器均为自研（`st/frontend.py` 895 行、
   `st/typecheck.py` 444 行、`st/interp.py` 1069 行），参照 IEC 61131-3 的子集实现。
   论文里应写「在我们的解释器语义下验证」，真机验证列为 future work。
2. **模型检查是「有界穷举 + 状态去重」，不是符号模型检查。**
   - 找到反例 → 结论可靠（真的违反）。
   - 界内没找到 → 只是「预算内未发现违反」，不能写成「已证明」。
   - 结果里 `traces` 撞到上限的题会标 `truncated=True`，这类题的结论只能写成
     「在 N 拍深度、M 条迁移预算内未发现违反」。
3. **LTL 只覆盖标量接口变量。** 下标访问（如 `buffer[1]`）在 LTL 里不可判定，
   这类性质降级成 `verified_by: simulation`（用参考解 + 用例覆盖），共 10 条。
4. **用例数口径：v1.1 文档写 75、v1.2 是 134。** 75 是 2026-10-24 18:50 的旧值（10 道题 77 条
   用例的早期草稿 75 条），v1.1 包内实为 77；v1.2 新增 5 道题 +57 条 = 134。
   **以 134 为准**，`datasets/selfmade/_index.json` 是机器生成的单一真源。

## 5. 常见操作

```bash
# 单题验证（含模型检查默认关闭时更快）
python -X utf8 scripts/verify_one.py self-hard-07 --no-mc

# 重建自建题 JSON（前 10 道 / 后 5 道分别重建，再统一导出参考解与索引）
python -X utf8 datasets/selfmade_build.py
python -X utf8 datasets/selfmade_new5.py
python -X utf8 tools/export_references.py

# 全部自建题的模型检查（慢，建议后台跑并重定向日志）
python -X utf8 tools/_t_mc_all.py > _mc.log 2>&1
```

> 改题目时的铁律：**先改 `datasets/selfmade_*.py`（生成脚本），不要直接手改 JSON**。
> JSON 是产物，手改会被下一次重建覆盖，而且会造成「代码与数据漂移」。
