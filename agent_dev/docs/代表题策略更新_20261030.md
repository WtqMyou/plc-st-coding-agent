## FIFO 绑定假设审计（10 月 31 日）

第五版自研 DeepSeek FIFO 候选通过了 27/27 条用例，但现有 LTL 检查记录了 S1/S4 违反。S1 反例先在容量 4 下存入三个元素，再把 capacity 改成 2，元素计数仍为 3。

已原样重放此轨迹：参考解和候选都在该拍违反 S1；若保持容量为 4，两份代码都不违反这一条轨迹上的 S1。证据为 evidence/portable_strategy_r5_20261030/fifo_binding_audit.json。这不能证明整项规约通过，也不能把该反例仅归因为模型生成错误。

原题要求从调用方缓冲区推导容量；参考源码注释还提及数组换长度时容量改变，但没有给出缩容后元素保留、丢弃或拒绝的完整规则。现有适配把绑定容量暴露为普通输入，检查器会逐拍改变它，却没有更换对应数组绑定。因此，固定容量的不同绑定与运行中动态换绑必须明确区分。已向用户请求确认；确认前保留原始判定与审计记录，不宣称 FIFO 已完整验证，也不擅自修改原始规约或 expected。
