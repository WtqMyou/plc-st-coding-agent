## 共同执行与验收约定

1. 每题实现一个FUNCTION_BLOCK。输入在扫描开始采样，输出在该拍执行结束后检查；下文“当拍”均指这一约定。
2. 每题独立实例，上电内部状态和输出按题内规定初始化。除特别写明外，上升沿按 `x AND NOT prevX` 计算，上电前值为FALSE。
3. BOOL输入每拍显式给出；测试表未列出的输入使用该组测试的基线值。不同测试组使用全新实例，同组按行顺序连续执行，不能逐行重建实例。
4. 所有REAL输入均为有限实数，不包含NaN或无穷。数值比较验收容差为 `1e-6 × max(1, abs(expected))`。门限和分支判断仍按题面精确规则执行，不能用该容差更改门限。
5. `Clamp(x,a,b)=min(max(x,a),b)`。计数变量建议DINT，累计量建议LREAL；类型可随目标环境调整，但须保留精度和范围。
6. LTL是候选规约，以“每拍结束后的输入输出记录”为轨迹。`G`表示总是，`X`表示下一拍，`prev`表示上一条轨迹记录。使用prev的性质用辅助量 `hasPrev` 跳过首拍；首拍行为由测试检查。部署到现有验证器前须核实语法和取值时点，不能直接把文本标成“验证通过”。
7. 数值算法的精确性主要靠独立计算的测试向量验证；LTL补充检查限幅、保持和优先级，不宣称证明闭环稳定性。

## P01 燃烧状态与氧量修正联锁

### 背景与目标

某教学锅炉已完成点火和火焰确认。正常燃烧时，氧量高于目标会使空气修正量减小。若失焰后仍继续执行这套调节，可能错误地把氧量升高当成空气过剩。本题要求实现运行阶段的氧量修正和故障联锁，不包含点火、吹扫或重新点火流程。

本题不假设失焰后氧量必然立即变成21%；测试会注入“失焰同时氧量升高”的输入轨迹，程序必须以燃烧状态判定优先。

### 接口

| 方向 | 名称 | 类型 | 含义 |
|---|---|---|---|
| 输入 | runRequest | BOOL | 上层发出的稳定燃烧运行请求；TRUE保证已经过上层点火确认 |
| 输入 | flameOK | BOOL | 火焰已确认信号 |
| 输入 | o2Valid | BOOL | 氧量仪表质量有效标志 |
| 输入 | o2PV | REAL | 烟气氧量，百分数数值，例如2表示2% |
| 输入 | baseAir | REAL | 基础空气命令，0～100% |
| 输入 | resetBtn | BOOL | 人工复位按钮，上升沿有效 |
| 输出 | fuelPermit | BOOL | 向上层提供的燃油运行许可 |
| 输出 | trimEnable | BOOL | 氧量修正是否投入 |
| 输出 | airTrim | REAL | 空气修正量，百分点，范围−10～10 |
| 输出 | airCommand | REAL | 空气命令，范围0～100% |
| 输出 | tripLatched | BOOL | 失焰故障锁存 |
| 输出 | o2Fault | BOOL | 氧量信号异常指示，不锁存 |

### 控制要求

1. 上电 `tripLatched=FALSE`。`airTrim`为每拍重算的比例修正，不设积分。
2. 当 `runRequest AND NOT flameOK` 时，当拍置位tripLatched。置位优先于任何复位。
3. 仅当resetBtn出现上升沿，且 `NOT runRequest AND NOT flameOK` 时，允许清除故障锁存。停机、火焰信号恢复、氧量恢复均不能自行清锁。
4. `fuelPermit = runRequest AND flameOK AND NOT tripLatched`。复位成功当拍runRequest必须为FALSE，因此复位本身不会供油。
5. `o2Fault = NOT o2Valid OR o2PV<0 OR o2PV>21`。氧量异常仅禁用修正，不单独触发失焰锁存。
6. `trimEnable = fuelPermit AND NOT o2Fault`。允许修正时，目标氧量2%，`airTrim=Clamp(2×(2−o2PV),−10,10)`；否则airTrim必须为0，不能保持先前负修正。
7. 若fuelPermit为TRUE，`airCommand=Clamp(baseAir+airTrim,0,100)`；否则airCommand=0。本题的0仅表示本功能块退出空气调节，实际空气执行机构由上层停机/吹扫模块接管。
8. baseAir由调用方保证在0～100内。runRequest与失焰同拍出现时，仍按失焰处理；本题不能拿来直接处理点火等待阶段。

### 测试示例

基线：`baseAir=50, o2Valid=TRUE, resetBtn=FALSE`。以下为同一实例。

| 拍 | runRequest | flameOK | o2PV | resetBtn | fuelPermit | trimEnable | airTrim | airCommand | tripLatched |
|---|---|---|---|---|---|---|---|---|---|
| 1 | TRUE | TRUE | 2 | FALSE | TRUE | TRUE | 0 | 50 | FALSE |
| 2 | TRUE | TRUE | 4 | FALSE | TRUE | TRUE | −4 | 46 | FALSE |
| 3 | TRUE | FALSE | 10 | FALSE | FALSE | FALSE | 0 | 0 | TRUE |
| 4 | TRUE | FALSE | 21 | TRUE | FALSE | FALSE | 0 | 0 | TRUE |
| 5 | TRUE | TRUE | 2 | FALSE | FALSE | FALSE | 0 | 0 | TRUE |
| 6 | FALSE | FALSE | 21 | TRUE | FALSE | FALSE | 0 | 0 | FALSE |
| 7 | TRUE | TRUE | 2 | FALSE | TRUE | TRUE | 0 | 50 | FALSE |

独立边界组：正常有焰运行下，氧量22使o2Fault=TRUE且airTrim=0；氧量有效标志FALSE也须如此。氧量21且有效时不是仪表越界，airTrim限幅为−10；不能仅凭21认定失焰。补测上下限裁剪、上电无请求、无效复位后按住按钮再转入复位条件等场景。

### 候选LTL

```text
G((runRequest AND NOT flameOK) -> (tripLatched AND NOT fuelPermit))
G(tripLatched -> (NOT fuelPermit AND NOT trimEnable))
G(NOT trimEnable -> airTrim = 0)
G((airCommand >= 0) AND (airCommand <= 100))
G((hasPrev AND prev(tripLatched) AND NOT resetAccepted) -> tripLatched)
```

辅助量resetAccepted为满足第3条且未触发失焰置位的复位事件，由独立测试监视器按输入边沿计算。不能由被测程序自行决定该量。

### 主要抓错点

只看高氧就减空气；失焰保留负修正；火焰恢复就自动解锁；复位与运行请求同时来时放行；把按钮电平当成上升沿。

## P02 合格蒸汽产量及净收益累计

### 背景与目标

锅炉生产的蒸汽只有温度、压力同时合格才能计入有效产量及收入，但燃料消耗无论产品合格与否都计成本。实现一个按采样区间累计产量与净收益的功能块。

### 接口

| 方向 | 名称 | 类型 | 含义 |
|---|---|---|---|
| 输入 | enable | BOOL | TRUE时进行累计 |
| 输入 | resetBtn | BOOL | 上升沿清零 |
| 输入 | dt | LREAL | 本次采样代表的区间长度，秒，合法范围0＜dt≤10 |
| 输入 | steamFlow | LREAL | 蒸汽流量，kg/s，合法范围0～90 |
| 输入 | fuelFlow | LREAL | 燃油流量，kg/s，合法范围0～6 |
| 输入 | steamTemp | LREAL | 蒸汽温度，℃ |
| 输入 | steamPressure | LREAL | 蒸汽压力，kPa |
| 输出 | qualified | BOOL | 本拍输入是否满足蒸汽质量条件 |
| 输出 | dataFault | BOOL | dt或流量越界 |
| 输出 | qualifiedTon | LREAL | 合格蒸汽累计吨数 |
| 输出 | fuelTon | LREAL | 燃油累计吨数 |
| 输出 | revenue | LREAL | 累计收入，元 |
| 输出 | cost | LREAL | 累计燃料成本，元 |
| 输出 | netProfit | LREAL | 净收益，元，允许负数 |

### 控制要求

1. 上电五个累计输出均为0。单价固定：合格蒸汽280元/吨，燃油1500元/吨。
2. 温度在[447,453]℃且压力在[3750,3850]kPa时qualified=TRUE，否则FALSE；两个区间均包含端点。qualified不受enable影响，表示质量判定，不表示本拍已累计。
3. 当dt不在合法范围，或任一流量不在合法范围时，dataFault=TRUE。温度、压力偏离质量区间表示产品不合格，不属于本题dataFault。
4. resetBtn上升沿优先：清零所有累计值，当拍不累计；qualified与dataFault仍按本拍输入更新。按住复位不重复清零。
5. 非复位拍，仅当enable=TRUE且dataFault=FALSE时累计。把输入视为本次dt区间内的代表值，使用矩形积分，不使用梯形积分。
6. 燃油增加量 `fuelFlow×dt/1000` 吨，无论蒸汽合格与否均累计。合格蒸汽增加量仅在qualified=TRUE时为 `steamFlow×dt/1000` 吨。
7. 每拍由累计质量计算 `revenue=qualifiedTon×280`，`cost=fuelTon×1500`，`netProfit=revenue−cost`。不对中间值逐拍四舍五入，不将负收益截为0。
8. enable=FALSE或dataFault=TRUE时，累计量整体保持，不只更新其中一部分。停用或故障期间不补算遗漏区间。

### 测试示例

基线：enable=TRUE、resetBtn=FALSE。以下为同一实例。

| 拍 | dt | steamFlow | fuelFlow | 温度 | 压力 | qualified | 合格吨数 | 燃油吨数 | 收入 | 成本 | 净收益 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 1 | 20 | 1 | 450 | 3800 | TRUE | 0.020 | 0.001 | 5.6 | 1.5 | 4.1 |
| 2 | 2 | 20 | 1 | 446 | 3800 | FALSE | 0.020 | 0.003 | 5.6 | 4.5 | 1.1 |
| 3 | 1 | 20 | 1 | 447 | 3750 | TRUE | 0.040 | 0.004 | 11.2 | 6.0 | 5.2 |
| 4 | 0 | 20 | 1 | 450 | 3800 | TRUE | 0.040 | 0.004 | 11.2 | 6.0 | 5.2 |

独立组：首次输入dt=1、steamFlow=0、fuelFlow=1，净收益应为−1.5元。补测453/3850端点、仅压力不合格、流量负值及上界、停用保持、复位优先、复位按住时下一拍正常累计。

### 候选LTL

```text
G(qualified <-> (steamTemp >= 447 AND steamTemp <= 453
                AND steamPressure >= 3750 AND steamPressure <= 3850))
G((qualifiedTon >= 0) AND (fuelTon >= 0))
G(resetEdge -> (qualifiedTon = 0 AND fuelTon = 0))
G((hasPrev AND NOT resetEdge AND (NOT enable OR dataFault))
  -> (qualifiedTon = prev(qualifiedTon) AND fuelTon = prev(fuelTon)))
```

浮点金额关系按共同容差由测试判定，不要求验证器用浮点精确相等证明。

### 主要抓错点

遗漏kg到吨换算；漏乘dt；温度和压力用OR；只算合格时燃油成本；按住复位永远清零；把负净收益裁成0。

## P03 温度模糊控制与输出约束

### 背景与目标

某教学加热过程根据温度偏差与偏差变化率修正加热功率。给定完整的零阶Sugeno规则，实现控制器，不要求模型自行设计规则或整定参数。

### 接口

| 方向 | 名称 | 类型 | 含义 |
|---|---|---|---|
| 输入 | enable | BOOL | 控制投入 |
| 输入 | resetBtn | BOOL | 上升沿复位 |
| 输入 | sensorValid | BOOL | 温度信号有效 |
| 输入 | setpoint | REAL | 设定温度，℃ |
| 输入 | temperature | REAL | 实测温度，℃ |
| 输入 | dt | REAL | 采样周期，秒，合法范围0＜dt≤10 |
| 输入 | bias | REAL | 基础加热功率，调用方保证0～100% |
| 输出 | power | REAL | 加热功率，0～100% |
| 输出 | correction | REAL | 模糊修正量，百分点 |
| 输出 | fault | BOOL | 信号无效或采样周期非法 |

### 控制要求与算法

1. 误差 `e=setpoint−temperature`。误差变化率 `de=(e−prevE)/dt`。上电、复位、停用或故障后，第一次有效控制拍令de=0，不能用清零的prevE制造尖峰。
2. 正常有效拍结束后保存prevE=e，并标记已有历史。复位边沿、enable=FALSE或fault=TRUE时：power=0、correction=0、清除历史有效标志。当拍不计算正常输出。
3. `fault=NOT sensorValid OR dt<=0 OR dt>10`，每拍独立计算，不锁存。复位不掩盖fault。
4. 归一化输入 `x=Clamp(e/10,−1,1)`，`y=Clamp(de/2,−1,1)`。先计算实际误差及变化率，再分别归一化，不用已裁剪的x计算变化率。
5. 对任意归一化量z，三个隶属度：`μN(z)=max(−z,0)`，`μZ(z)=1−abs(z)`，`μP(z)=max(z,0)`。z已限制在[−1,1]，三个隶属度之和为1。
6. 规则触发强度为两个隶属度的乘积，不能用min代替。按下表取各规则的单点输出值c。

| 误差x \ 变化率y | N | Z | P |
|---|---|---|---|
| N | −30 | −20 | −10 |
| Z | −10 | 0 | 10 |
| P | 10 | 20 | 30 |

7. `correction=Σ(w×c)/Σw`，九条规则均参与；在上述隶属度定义下Σw=1。不能只选权重最大的规则。
8. `power=Clamp(bias+correction,0,100)`。不额外加入积分、输出斜坡或滤波。
9. 同拍优先级为“复位边沿或停用或故障→输出0”，其次才是正常计算。即使bias非0，停用输出仍为0。

### 测试示例

基线：enable=TRUE、sensorValid=TRUE、resetBtn=FALSE、setpoint=100、dt=1、bias=50。以下为同一实例。

| 拍 | temperature | e | de | x | y | correction | power |
|---|---|---|---|---|---|---|---|
| 1 | 100 | 0 | 0 | 0 | 0 | 0 | 50 |
| 2 | 95 | 5 | 5 | 0.5 | 1 | 20 | 70 |
| 3 | 95 | 5 | 0 | 0.5 | 0 | 10 | 60 |
| 4 | 105 | −5 | −10 | −0.5 | −1 | −20 | 30 |

独立混合权重组：新实例第1拍temperature=96（e=4、de=0），correction=8、power=58；第2拍temperature=95、dt=1，x=0.5、y=0.5，四条规则各权重0.25，correction=15、power=65。

补测正负饱和、bias=95时上限裁剪、bias=5时下限裁剪、dt非法、停用后恢复首拍de=0、故障恢复首拍de=0、复位同时有大偏差。

### 候选LTL

```text
G((power >= 0) AND (power <= 100))
G((correction >= -30) AND (correction <= 30))
G((NOT enable OR fault OR resetEdge) -> (power = 0 AND correction = 0))
```

### 主要抓错点

误差符号反向；首拍微分尖峰；用min代替乘积；只选择一条规则；先裁剪误差再求导；遗漏bias或输出限幅。闭环超调、稳定时间不作为本题基础判分指标。

## P04 蒸汽超压联锁与故障线索诊断

### 背景与目标

锅炉汽包压力越限时需要触发保护，同时为操作员提供可追溯的故障线索。仅凭“压力高”不能唯一确定原因，因此本题输出基于已给证据的疑似原因位掩码，不能将规则匹配说成真实因果证明。

### 接口

| 方向 | 名称 | 类型 | 含义 |
|---|---|---|---|
| 输入 | runRequest | BOOL | 运行请求 |
| 输入 | pressureValid | BOOL | 压力仪表有效 |
| 输入 | pressure | REAL | 汽包压力，kPa；调用方保证0～6000 |
| 输入 | fuelFlow | REAL | 燃油流量，kg/s，0～6 |
| 输入 | steamFlow | REAL | 蒸汽出口流量，kg/s，0～90 |
| 输入 | outletCmd | REAL | 蒸汽出口阀命令开度，0～100% |
| 输入 | outletFeedback | REAL | 蒸汽出口阀实际开度反馈，0～100% |
| 输入 | resetBtn | BOOL | 人工复位，上升沿有效 |
| 输出 | tripLatched | BOOL | 保护锁存 |
| 输出 | fuelPermit | BOOL | 本模块的燃油许可 |
| 输出 | currentCauseMask | WORD | 当前证据位掩码 |
| 输出 | latchedCauseMask | WORD | 本次故障累计证据位掩码 |
| 输出 | diagnosticActive | BOOL | 当前是否有诊断证据 |

### 诊断位定义

| 位值 | 证据含义 | 判定条件 |
|---|---|---|
| 16#0001 | 压力反馈不可信 | pressureValid=FALSE |
| 16#0002 | 出口阀疑似未按命令开启 | 压力高，且outletCmd≥50、outletFeedback≤10连续3拍 |
| 16#0004 | 高燃油、低蒸汽负荷组合 | 压力高，且fuelFlow≥4、steamFlow≤10 |
| 16#0008 | 其他或证据不足 | 压力高，但本拍位2和位4均不成立 |

“压力高”定义为pressureValid=TRUE且pressure≥4500。位2、位4可以同时成立；位8不与位2、位4同时成立。阀命令与反馈偏差只是线索，不能进一步断言一定是机械卡涩。

### 控制要求

1. 上电tripLatched=FALSE、累计掩码为0、阀证据计数为0。
2. 只有runRequest=TRUE时开展故障诊断。runRequest=FALSE时currentCauseMask=0，阀证据计数清0。
3. 运行期间pressureValid=FALSE时，不使用pressure数值判断超压，当拍currentCauseMask=16#0001，并清零阀证据计数；同拍触发保护锁存。
4. 运行且压力有效时，按表计算证据。位2的连续计数只有“压力高且命令≥50且反馈≤10”每拍全部成立时增加，饱和于3；任一条件不成立即归0，第3拍即输出位2。
5. 任一诊断位成立都置位tripLatched。正常运行但无超压时currentCauseMask=0。
6. 故障锁存期间，每拍执行 `latchedCauseMask=latchedCauseMask OR currentCauseMask`。因此早期“证据不足”可以和后来取得的具体线索同时留在历史掩码中；不要把历史掩码误解为当前诊断。
7. 仅在resetBtn上升沿、runRequest=FALSE、pressureValid=TRUE且pressure≤4200时清除锁存及历史掩码。其他复位均不接受；置位优先于复位。
8. `fuelPermit=runRequest AND NOT tripLatched`。这是单一保护模块许可，不包含P01的火焰检查；上层需要将不同模块的许可做逻辑合取。
9. 不得只因蒸汽压力低于4500就自动清锁；诊断证据消失也不清除历史。保护不等待阀证据满3拍：超压第一拍会立即通过位4或位8触发。

G((runRequest AND pressureValid AND pressure >= 4500)
  -> (tripLatched AND NOT fuelPermit))

## P05 串级PI控制手自动无扰切换

### 背景与目标

教学加热装置采用“温度主回路→流量副回路”串级控制。主回路产生流量设定值，副回路产生阀门命令。实现三种运行模式、PI计算与积分跟踪，使副回路在模式切换当拍不发生输出跳变。

为使答案唯一，本题指定离散PI形式、参数、限幅及切换规则，不要求调用厂商PID库。模型只验证算法和切换行为，不要求在未知被控对象上证明调节性能。

### 接口

| 方向 | 名称 | 类型 | 含义 |
|---|---|---|---|
| 输入 | mode | INT | 0：全手动；1：副回路自动、主回路手动；2：串级自动 |
| 输入 | resetBtn | BOOL | 上升沿复位 |
| 输入 | dt | REAL | 采样秒数，0＜dt≤10 |
| 输入 | tempSP | REAL | 温度设定，℃ |
| 输入 | tempPV | REAL | 温度测量，℃ |
| 输入 | flowPV | REAL | 流量测量，kg/s |
| 输入 | manualFlowSP | REAL | 主回路手动给定，0～50kg/s |
| 输入 | manualValve | REAL | 副回路手动输出，0～100% |
| 输出 | flowSP | REAL | 本拍实际副回路流量设定，0～50kg/s |
| 输出 | valveCommand | REAL | 阀门命令，0～100% |
| 输出 | fault | BOOL | 非法mode或dt |

### 固定算法

主回路参数 `KpT=1, KiT=0.2`；副回路参数 `KpF=2, KiF=0.5`。两回路均为正误差增加输出，PI采用位置式、先更新积分再计算输出。

自动计算一个回路时，给定误差e、积分状态I及输出限幅[L,H]：

```text
Itrial = I + Ki × e × dt
output = Clamp(Kp × e + Itrial, L, H)
I = output − Kp × e
```

最后一行是本题指定的积分回算，不可换成“积分超限时全部停止”等其他策略。

### 模式、初始化与切换规则

1. fault在mode不属于0/1/2，或dt≤0、dt>10时为TRUE。手动设定值由调用方保证合法。
2. 首拍、resetBtn上升沿、fault=TRUE时，执行初始化分支：`flowSP=manualFlowSP`、`valveCommand=manualValve`，按下文第3条跟踪两个积分，标记“尚未进入正常模式”。本拍不做积分更新。fault时该行为是题设的手动接管，不是其他安全模块的最终输出。
3. 跟踪积分的统一公式：`IT=flowSP−KpT×(tempSP−tempPV)`；`IF=valveCommand−KpF×(flowSP−flowPV)`。IT和IF是允许为负的内部状态。
4. 初始化后的第一拍合法非复位扫描也作为模式进入拍处理，不能直接积分。
5. 只要mode变化或发生首次模式进入，该拍采用下列切换分支，不做任何PI积分：
   - mode为0或1：flowSP取本拍manualFlowSP。
   - mode为2：flowSP保持上一拍flowSP，不能跳到新主回路计算值。
   - 三种模式均令valveCommand保持上一拍valveCommand，并按第3条跟踪IT、IF。
   - 记录当前mode，之后才进入正常运行。
6. 模式不变的正常拍：
   - mode=0：flowSP=manualFlowSP，valveCommand=manualValve；按第3条跟踪两个积分。
   - mode=1：flowSP=manualFlowSP；IT跟踪本拍flowSP。副回路用 `eF=flowSP−flowPV` 按固定PI算法计算valveCommand及IF。
   - mode=2：先以 `eT=tempSP−tempPV` 计算主回路flowSP及IT，再以本拍flowSP计算副回路valveCommand及IF。主回路限幅[0,50]，副回路限幅[0,100]。
7. “无扰”精确定义为第5条中，模式切换当拍valveCommand与上一拍相等；进入串级当拍flowSP也与上一拍相等。后续正常积分引起的输出变化不算切换跳变。
8. 切入手动当拍仍保持阀输出，下一拍才采用manualValve。该一拍跟踪延迟是本题刻意约定，避免操作员手动值与当前输出不一致时产生切换跳变。
9. 首拍及复位/故障初始化可以改变输出，不要求相对上一拍无扰。不能把本题PI输出接管规则当成失焰或超压保护；最终执行机构仍须服从独立联锁。

### 测试示例

基线：dt=1、resetBtn=FALSE、tempSP=100、tempPV=90、flowPV=10、manualFlowSP=10、manualValve=40。以下为同一实例。

| 拍 | mode | flowSP | valveCommand | 说明 |
|---|---|---|---|---|
| 1 | 0 | 10 | 40 | 首拍初始化，IT=0，IF=40 |
| 2 | 0 | 10 | 40 | 首次模式进入，跟踪，无积分 |
| 3 | 1 | 10 | 40 | 切副回路自动，阀输出不变 |
| 4 | 1 | 10 | 40 | 流量偏差0，正常PI输出保持 |
| 5 | 2 | 10 | 40 | 切串级当拍主副输出均保持 |
| 6 | 2 | 12 | 45 | 主回路IT=2；副回路误差2、IF=41，输出45 |
| 7 | 2 | 14 | 51 | 主回路IT=4；副回路误差4、IF=43，输出51 |
| 8 | 0 | 10 | 51 | manualValve改为20，但切手动当拍仍保持51 |
| 9 | 0 | 10 | 20 | 模式稳定后采用手动输出20 |

第8、9拍manualValve=20，其余输入不变。补测1→2→1→0各方向切换、温度设定改变、流量扰动、主副上限和下限、积分回算后的恢复、非法dt及mode、故障后重新进入自动、复位按住不重复触发。

### 候选LTL

```text
G((flowSP >= 0) AND (flowSP <= 50))
G((valveCommand >= 0) AND (valveCommand <= 100))
G((hasPrev AND switchAccepted) -> valveCommand = prev(valveCommand))
G((hasPrev AND switchAccepted AND mode = 2) -> flowSP = prev(flowSP))
```

switchAccepted由独立监视器按上述初始化状态、合法输入和mode变化判定；复位或故障初始化不属于该事件。真实浮点输出的相等使用测试容差实现。

### 主要抓错点

自动前未跟踪积分；主副回路更新次序反；切入串级立即积分；切入手动立即跳到不一致的手动值；积分状态错误限为非负；输出饱和后积分未回算。
