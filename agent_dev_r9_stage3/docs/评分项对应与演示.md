## 5 分钟技术演示

1. 展示 architecture.mmd、实验协议与当前冻结清单，说明 DeepSeek/MiniMax 两模型、两框架、75 元总预算，以及离线检查、真实试跑、正式实验的区分。
2. 展示 evidence/repair_guard_r7_20261031/validation.json 中的 100 项回归、435 条参考解用例与实际 CLI 离线桥接。需要重跑时，使用 `scripts/validate_continuation.py --out evidence/新的演示目录`，不覆盖旧日志。
3. 打开 platform_projects 中储罐联锁 self-easy-02、闸门状态机 self-medium-03、批次控制 self-hard-02 三类工程，查看编译日志与生成产物。
4. 运行 `python -B -X utf8 scripts/native_controls.py --platform openplc`，展示正确程序通过、故意缺失赋值表达式的程序失败。CODESYS 同样执行 `--platform codesys`。
5. 展示第七版实际候选（其中 16 条兼容代表题来自第六版，见 pilot_reuse.json）的供应商身份、用量、代码与真实编译日志；正式汇总仅在四组各覆盖 35 题后使用。旧 offline_matrix_v2.1 的 fixture 结果只能说明接口可运行。
6. 展示 FIFO 例子：真实候选即使通过 27 条用例，仍可能在复位与入队同时发生时违反复位优先规约。容量 2/4 按固定绑定检查，不能宣称支持动态缩容或无限状态证明。

## 接手成员的报告材料

报告可以直接引用验收报告、平台安装记录、修订记录、实验协议和 project_index。统计数字须取本轮 JSON/CSV，不能沿用成员一历史文档中的全规约通过结论。

当前两框架统一使用 portable-frame-v4。生成后的代码不会被静默改写；适配发生在评测前的题面和接口冻结阶段。原 v2.1 的平台工程及离线全题矩阵作为历史证据保留。

    python -B -X utf8 scripts/run_frozen_campaign.py

启动前先核对 active_run.json 的实际进程，避免已有流程运行时重复启动。当前流程已完成身份、协议和输出边界核验，使用同一共享账本；包内预算快照不可用于退回已消耗金额。

## 已知数据边界

通用 VARIANT FIFO 未量化任意调用方类型/容量，原契约的形式检查返回无法判定。适配版是 DINT 有界特化。self-hard-04 的 rotated 字段沿用既有输入契约，表示轮换请求。五道新题的工艺合理性仍由组内评审确认；工程修订详见二次更新整合说明。
