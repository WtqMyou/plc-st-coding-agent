# STBench 数据集规范（公共题 20 道 · 成员 1 交付件）

> 版本：2026-10-24。适用范围：`datasets/public/public-*.json`（20 道公共题）与
> `datasets/public/tests/*.reference.st`。自建题（`datasets/selfmade/`）沿用本文的
> 同一条口径，差异只在参考解的存放形式（见 §6）。
>
> 本文件是**数据集的口径定义**：只说"什么算合格的数据"，不解释工具实现。

## 1. 数据集定位

STBench 判分分三层，数据要为三层各自提供输入：

| 层 | 数据依赖 | 本数据集提供 |
| --- | --- | --- |
| 编译（语法 + 静态语义） | 题目接口 | `variables`（名字/类型/方向） |
| 仿真（操作语义） | 逐周期用例表 | `test_cases`（输入向量 + 期望输出） |
| 有界模型检查（LTL） | 形式化性质 | `specs`（`ltl` + 文字说明） |

因此每道题的**最低合格线**是三件套齐全：接口表 + 用例 + 规约。缺任何一项，
该题在 `scripts/check_dataset.py` 里就是硬性失败，不能进实验。

## 3. 接口规范

- `variables[].direction`：`input`（输入）/ `output`（输出）/ `inout`（输入输出）。
  省略 `direction` 视为输出。
- 名字与类型**照抄原题**（含大小写、`ARRAY[1..5] OF ...`、`STRING(254)`、`UDINT`）。
  不改名、不改类型宽度——模型看到的接口就是题目原始接口。
- 结构体：题目给结构体变量时，`variables[].fields` 必须填全（字段名/类型/说明），
  参考解里另需 `TYPE ... END_TYPE` 定义。字段缺失等于让模型瞎猜，属**题目缺陷**。
- 可变长数组用 `ARRAY[*]`，实际长度由整数输入（如 `count`）给出，用例必须覆盖
  "长度 < 容量"与"长度 = 容量"两种情形。

## 4. 测试用例规范

### 4.1 字段

```json
{
  "tc_id": "e01-1",
  "inputs":        { "sensor": true },
  "const_inputs":  { "reset": false },
  "expected":      { "Pump_Motor": true },
  "note":          "瓶子到位 → 泵启动、其余执行机构不动",
  "init":          {},
  "mode":          "",
  "cycles":        1,
  "expect_full":   false
}
```

- `inputs`：本周期赋值；未给值的 BOOL 输入按 FALSE 处理，非 BOOL 输入沿用上一周期值。
- `const_inputs`：整条用例期间每周期都重新写入的输入，用于"操作员保持某个按钮"。
- `expected`：**非空**，键名必须是题目接口里的输出名；比较规则见 4.1.1。
- `note`：一句话写清"场景 → 期望"，不要写"测试用例 1"这种废话。
- `cycles`：本用例连续扫描的拍数，之后才断言（去抖、延时、计数都用它表达）。
- `expect_full`：置 true 时必须断言**全部**输出变量，用于"其他执行机构必须不动"的负例。

#### 4.1.1 结构化输出的断言形态

比较在 `stbench/st/interp.py::_match()` 里统一做，运行期的包装类型会在**比较层**解包：

| 输出类型 | 写法 | 规则 |
| --- | --- | --- |
| 标量（BOOL/INT/REAL…） | `{"out": 12}` | 浮点按 1e-6 相对误差，其余严格相等 |
| 结构体 | `{"out": {"field": 1.0}}` | **字段子集**：只比写出来的字段，未写字段不参与判定 |
| 数组 | `{"out": [1, 2, 3]}` | 长度必须与实际数组一致，逐元素比较（`ARRAY[0..4]` 从下标 0 起排列） |
| 结构体数组 | `{"out": [{"f": 1}, {"f": 2}]}` | 元素个数对齐，逐元素按结构体规则 |
| VARIANT | `{"out": 10}` 或按内层类型的形态 | 取壳后按内层值比较 |

不允许写 `out[1].field` 这种路径（审计会判"用了接口没声明的变量"）。

### 4.2 两种模式

| 模式 | 语义 | 什么时候用 |
| --- | --- | --- |
| `single`（默认） | 每条用例一个**全新实例**，跑 `cycles` 拍后只看末态 | 输入→输出映射、组合逻辑、单拍保持 |
| `sequence` | 同 mode 的用例按列表顺序在**同一实例**上连续扫描，状态跨用例保留 | 状态机、FIFO、计数器、完整工艺周期 |

`single` 下新实例初值只有 0/FALSE；`init` 只对 `inout` 数组/结构体有意义，
**禁止**靠 `init` 伪造非零中间状态。想测"从某中间态出发"就换 `sequence` 或
在该条用例里用 `cycles` 把状态演进过去。

### 4.3 覆盖要求（硬性）

1. 每个 `direction="output"` 的变量至少被断言一次。
2. 每条用例 `expected` 非空；`tc_id` 题内唯一；不得出现接口外变量名。
3. 每个输入变量至少出现在一条用例里。
4. 量级：easy 6~8 条、medium 8~12 条、hard 10~14 条。
5. 必含场景：正常路径、边界值（0 / 负 / 上下限 / 16#FFFF 等类型边界）、
   优先级与互斥（急停压过一切）、复位与恢复、**负例**（不该动作时不动作，≥1/4）。

用例期望值一律由**参考解推演**得出，不许"照着模型输出回填"——那会让指标自证。

## 5. LTL 规约规范

### 5.1 语法子集

- 时序算子：`G`（总是）、`F`（最终）、`X`（下一拍）、`U`（直到）。
- 逻辑：`AND` `OR` `NOT` `->`；比较：`=` `<>` `<` `<=` `>` `>=`。
- 辅助：`rising(x)`、`falling(x)`、`prev(x)`、`no_array_overflow(...)`。
- `prev(x)` 只能放在 `G(...)` 内；裸露在顶层的 `prev` 在第一拍无定义，恒不可判定。

### 5.2 条目字段

```json
{ "sid": "S1", "text": "当液位 ≥ 85.0 时，高液位报警必须在当周期置位。",
  "ltl": "G(tankLevel >= 85.0 -> alarmHigh)", "kind": "safety", "verified_by": "plcverif" }
```

- `text`：中文，"当…时，必须…"；`ltl`：可直接送模型检查器的公式。
- `kind`：`safety`（不出现坏事）/ `sequencing`（先后顺序）/ `liveness`（最终发生）/
  `data`（数据聚合性质）。
- `verified_by`：`plcverif` = 真的跑过有界模型检查且 hold；`simulation` = 只能由
  用例验证的数据性质（此时 `ltl` 留空）。**不许**两者都空，也不许不跑就写 `plcverif`。
- 每题 3~6 条，至少 1 条 `safety`，尽量有 1 条 `liveness` 或 `sequencing`。

### 5.3 结论口径（必须如实写进报告）

模型检查是**有界**的：`mc_max_depth` 拍内、`mc_max_traces` 条轨迹内没找到反例。
只能说"有界内未发现违反"，不能写成"证明成立"。撞到轨迹上限时报告必须显示 truncated。
测试通过率与规约成立率是两个指标，不得合并成一个"正确率"。

## 6. 参考解规范

- 单个 `FUNCTION_BLOCK`，接口与题目 `variables` 逐项一致（名称、方向、类型）。
- 逐条对应 `requirements` 的编号需求，用 `(* R1: ... *)` 注释标到实现处。
- 边沿检测手写：`edge := btn AND NOT prevBtn; prevBtn := btn;`（先算后更新）。
  平台无 `R_TRIG`/`TON`/`TOF`。
- 存放：公共题 `datasets/public/tests/<pid>.reference.st`（按文件，便于换人重跑）；
  自建题写在 `stbench/selfmade_refs.py` 的 `REFS` 常量里（同一批人维护，避免漂移）。
- 参考解**不进提示词**：它只用于证明用例可满足、以及 mock 通道的全链路冒烟。

## 7. 平台能力边界与已登记偏差

实测于 2026-10-24，结论以本表为准（旧交接文档里"medium-08 / hard-04 做不了"的说法已过期）：

| 能力 | 状态 | 数据侧处理 |
| --- | --- | --- |
| `T#...` 时间字面量 | **不可用**（解析为 0，TIME 比较恒真） | 计时/去抖改用**扫描周期计数**，用例按周期数断言，`note` 注明该偏差 |
| 整结构体赋值 `a := b` | 不支持（解析报错） | 逐字段赋值；`r := arr[i]` 取元素可用 |
| `R_TRIG`/`TON`/`TOF` | 未实现 | 手写边沿与计数 |
| `VARIANT` 读写 | 可用 | hard-04 正常出题 |
| `LEN` / 字符串下标 / `STRING_TO_INT` | 可用 | medium-08 IPv4 解析正常出题 |
| `ARRAY[*]` 可变长 | 可用（长度由输入给出） | medium-02 用例覆盖长度边界 |
| 结构体/数组/VARIANT 输出的断言 | **可用**（2026-10-24 起） | `_match()` 比较层解包，写法见 §4.1.1；此前"结构体输出断言不了"的结论已过期 |
| `LTIME` 接受整数常量 | 不支持（`LTIME := 0` 报 INT→LTIME 不匹配） | 需要上电清零时写 `acc - acc`（等价于 0），easy-04 实测可用 |
| MC 输入域含 inout/结构体名 | 会直接报"输入域里这些名字在程序中不存在" | 已修：`driver._collect_domains` 只收 `direction==input`；`init` 喂 inout 初值的通道不受影响 |
| `prev(x)` 首拍取值 | 上电存储区清零 → 首拍前值视作 0 | 边沿/变化类题必须把"首拍前值 = 0"写进规约或 `note`（easy-02 S6 已写明）；否则实现之间对不上 |
| LTL 里 `prev(x)` 参与比较 | 解析报错（`括号不配对`） | 写成 `G(NOT (prev(x) = v) -> ok)`；`G(a OR b)` 的顶层 OR 会被拆成原子（语义变成 `Ga ∧ Gb`），含 OR 要整体加括号 |
| `case_mode="sequence"` 的 MC | `verify_sequence` 不跑 MC | `verify_one.py` 已修：sequence 题先判用例、再跑 `verify()` 取 LTL 统计；`public_refs.py` 同理 |

任何为适配平台而偏离需求的实现，都必须在用例 `note` 与 §9 的偏差列里写明，
不允许静默改变语义。

## 8. 数据质量闸门（四层，缺一不可）

```bash
python -X utf8 stbench/public_refs.py            # 20 题参考解：编译 + 用例 + MC
python -X utf8 scripts/check_dataset.py  # 硬性审计（不带参数＝审全部公共题）：三件套齐全、覆盖、LTL 形态
python -X utf8 scripts/verify_one.py <pid>       # 单题细查（含 MC 明细）
python -X utf8 scripts/run_experiment.py --dataset public --provider mock --mock-use-refs --limit 3
```

前三层是数据自洽性，第四层是"判分全链路能跑通"的冒烟。任一层红都不许交。

### 9.2 两条会影响出题的平台事实（已验证）

1. **sequence 模式的 `inputs` 只认 `direction=="input"`**，把 inout 变量写进 `inputs`
   会被静默忽略；要给 inout 喂值必须走 `const_inputs`（常量通道不受 direction 限制）。
2. **LTL 的 `rising()/falling()` 只能出现在裸的顶层合取位置**，`NOT rising(x)` 会被
   当成原子文本，运行期报 `未定义的函数 RISING`；`prev(x)` 不能直接参与比较，
   写成 `G(NOT (prev(x) = v) -> ok)` 才解析。
