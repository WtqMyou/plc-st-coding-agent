## 本阶段修复

1. 本地枚举解析、名称解析、默认值与逐拍执行，支持显式整数值、基础整数类型、限定名及唯一非限定名。默认先选值为 0 的成员，没有则选第一个；类型和变量初值分别处理。
2. 区分普通枚举与显式 `strict`、`qualified_only` 属性，保留属性送入原生编译器；只读成员、歧义名称、未声明成员和非法声明仍拒绝。
3. 通用提示只在题面明确要求时采用上升沿复位，题面要求电平复位时按电平执行。没有改变题库、测试期望或为某题写入答案。
4. 新汇总读取实际的嵌套形式检查结果。

枚举规则以 [CODESYS 官方说明](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_datatype_enum.html) 和本机编译控制为依据；本轮只声明已实现并验证的语法范围，复杂枚举常量表达式等仍不支持。一个合法的最小枚举示例已通过真实 CODESYS；原付费候选仍可能同时存在其它语法错误，不能将这批失败全部归咎于检查器。

## 冻结的实验条件

- 题目：`self-medium-03`、`public-hard-04`，继续保留闸门状态机和 FIFO，不按本轮结果换题。
- 四组：自研/DeepSeek、Codex/DeepSeek、自研/MiniMax、Codex/MiniMax，各两题；第二题反向执行组别顺序。
- 模型和参数沿用原配置：DeepSeek 原生 Responses、MiniMax Chat；同模型的两框架使用相同上游协议、价格配置、16384 输出上限、420 秒请求时限和 450 秒请求窗口。
- 所有组单题 1200 秒，最多初始生成加一次修复；CODESYS 实际编译门控最多 120 秒，LTL 有界检查最多 30 秒，不复用裁判缓存。
- 采用编译成功后正常执行形式检查的共同策略，保留给修复轮的反馈。前轮未证明暂缓策略有稳定收益，不将其作为已验证改进。
- 这轮同时更新了评测器和通用提示，是流程准备性诊断，不能将新旧成绩差异归因于单一改动。旧付费固定候选另做不收费的重查以辨别检查器影响。
