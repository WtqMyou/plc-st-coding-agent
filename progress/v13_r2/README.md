4. **完整输出检查**：r2_judge.py 的 local_tests/evaluate 入口在进入旧检查器、缓存或真实编译前，检查每条 expect_full 用例是否列齐 output/inout，覆盖 single、sequence 和混合模式。缺失断言返回 E_TEST_CONTRACT 并标记 candidate_evaluated=false，这是测试数据错误，不作为已确认模型错误。部分断言只在 expect_full=false 时继续允许。
5. **原始与平台适配口径分开**：导出 CODESYS/OpenPLC 各35份适配 JSON，文件名分别带 `_codesys`、`_openplc`。contracts_manifest.json 记录原始JSON哈希、适配后哈希、接口是否改变和参考代码哈希。每个平台相对上游有7题接口变化，不能将这些通过数声称为原始接口通过率。

原始上游文件及生成器继续读取被冻结的 `../v13/upstream/`；修订只集中在 r2_revision.py，不再复制原始包或整套引擎。工作数据由统一入口生成，原始公共题JSON逐字节保留。r2_judge.py 是本版新增裁判入口；未修改旧 stbench 入口，旧入口仅用于复现历史版本。尚无 r2 付费实验启动器。

## 复现

从仓库根目录执行（不调用模型）：

```powershell
python -B -X utf8 progress/tools/v13_r2.py check
python -B -X utf8 -m unittest discover -s progress/tests -p test_v13_r2.py -q
```

check会检查r2数据、证据、r1及引擎哈希。build默认只比对生成结果；`build --write`、verify、rescore、freeze属于准备阶段，技术冻结后拒绝重写。后续修改须建立新版本。
