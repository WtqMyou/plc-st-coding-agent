课程参考程序按 STBench 解释器的约定，在运行时读取调用方数组边界并访问元素。该 CODESYS 模板在声明阶段已拒绝两个 VARIANT 参数。本次没有取得可保留该原型并在此模板编译的库或实现。CODESYS 文档支持将开放数组声明在 VAR_IN_OUT 中，元素类型写在声明里。这给出了已知元素类型的适配路径。文档中的泛型 ANY 用于输入参数，不能据此推断它能直接替代这两个可写参数。[CODESYS 开放数组](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_datatype_array.html) · [CODESYS 泛型输入](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_datatype_any.html)

## 同一目标环境如何验收

在解压后的工程根目录运行。前两条可在普通 Python 环境执行。后两条使用队友配置的 CODESYS 安装和模板，可用 `--executable` 和 `--template` 指向相同版本的实际位置。

```text
python -B -X utf8 verify_release.py
python -B -X utf8 platform_review/check.py
python -B -X utf8 platform_review/native_replay.py --check-env
python -B -X utf8 platform_review/native_replay.py --output native_replay_runs
```

原生复验工具使用已核对指纹的冻结编译脚本、平台封装和模板。它先编译正负对照，再分别编译课程参考与 DINT 专用 FB，并在一个新的运行目录内保留 `summary.json`、原生诊断与成功构建的离线启动文件。复现原题的预期失败也可使其“符合预期”，应读取每个对象自己的 `build.status` 作为实际编译状态。当前工作机没有这套安装和模板；P1 内的原题原生日志来自队友，DINT 版本在该模板上的原生编译状态为**待实测**。

若要验收函数块的真实调用，把专用 FB 和随附 PLC_PRG 安装在同一份模板副本中。模板已有 PLC_PRG 时，使用随附程序的声明、实现替换其对应区段；确认周期任务调用这一份 PLC_PRG。两个实例分别绑定 `ARRAY[-2..-1] OF DINT` 和 `ARRAY[7..10] OF DINT`。记录含两处调用的构建结果，再在 CODESYS 模拟环境从初态执行 14 次扫描，读取 `testComplete = TRUE`、`testPassed = TRUE`、`firstFailedStep = -1`。这一步有独立的结果，单独编译 FB 不能验证这两处调用及运行行为。[两组调用与逐拍检查](portable/PLC_PRG.st)
