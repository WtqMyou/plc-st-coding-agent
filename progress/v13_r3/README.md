# v1.3-judge-r3：字符串类型诊断与原生边界裁定

2026-11-08。只修订裁判入口，**数据继续使用已冻结的v1.3-review-r2，35题531用例**。r2、r1、R8/R9源码、题库、候选及历史结果均未改写；模型请求为0。

## 根因与修复

Codex/MiniMax/public-medium-08 的固定候选使用 `MID(ipText,1,idx) - '0'`。冻结前端的标准函数表把MID等标为返回string，但推断函数遗漏string类别，后续又缺少字符串算术操作数检查，因此该表达式漏过静态阶段，在Python解释器中抛出字符串减法TypeError。

历史及新跑的CODESYS编译均拒绝该代码；它没有被修成另一个程序。r3在独立StringChecker中恢复已知字符串函数返回类型，并对CODESYS口径的数值运算给出E_ARITH_TYPE；保留合法字符串比较、CONCAT及显式STRING_TO_INT转换。没有替换、修改或猴子补丁旧类型检查器。

r2完整输出断言闸门继续保留。新的evaluate入口先在**限时私有进程**中做预检，之后只使用剩余时间进行原生检查或旧worker评测；预检超时和工具失败仍是未决，不作为模型错误。缓存元数据中绑定新裁判版本、规则哈希和平台。

## 平台差异与建模范围

| 观察项 | CODESYS入口 | OpenPLC入口 | r3处理 |
| --- | --- | --- | --- |
| 原历史MID减字符串候选 | 拒绝 | 接受编译/打包 | CODESYS口径判类型错误；保留OpenPLC通过记录，不推断运行正确 |
| STRING加STRING | 拒绝 | 接受 | 平台规则分开；OpenPLC可使用已验证的字符串拼接行为 |
| 字符串显式转数值、比较、CONCAT | 接受 | 接受 | 正常执行本地用例 |
| 字符串下标减BYTE常量 | 接受 | 接受 | 旧解释器仍返回字符字符串，不能伪装成已支持的BYTE执行语义；保留未建模状态 |

共20项新原生对照（包括预期失败），源码、编译器身份、状态和工程位置均保存。最初“两平台都拒绝原候选”的假设被OpenPLC结果否定；观察记录未删除，策略据此按平台拆分。OpenPLC入口的接受不代表已经下载或运行PLC，也不证明表达式的功能语义。

对本地无法建模的程序，若调用者提供原生后端，r3可在剩余预算内进行编译边界裁定：原生明确拒绝才记candidate_native_error；原生通过则继续保留未决，不算功能通过；工具异常或超时也不算候选错误。单独调用local_tests不会暗中启动编译器。

140题次重评分中另外遇到自研MiniMax/public-medium-08的CHAR、转换写法及索引建模问题。按统一边界规则补做1次CODESYS编译，得到“Unknown type CHAR”、UDINT转换语法等错误，归为原生编译失败。该候选也未改写。

## 使用与下一步

统一入口为r3_judge.local_tests/evaluate；默认按适配任务中的平台选择规则，无平台信息时使用CODESYS主口径。OpenPLC-only运行不允许偷偷采用CODESYS规则，要求CODESYS的运行也不能借OpenPLC扩展放行。BYTE索引等未实现的语义依然明确标为未建模；本批140题次未决清零不代表所有合法ST都已支持。

从仓库根目录执行，不调用模型：

```powershell
python -B -X utf8 progress/tools/v13_r3.py check
python -B -X utf8 -m unittest discover -s progress/tests -p test_v13_r3.py -q
```
