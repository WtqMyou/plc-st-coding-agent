# 11.11队友交付包F1.4：分析与采纳建议

核验日期：2026年11月11日。来件为`STBench_F1.4_课程原题与13题合并_交付包.zip`，SHA-256为`23805581237f6da70586b26dd55899619d917310c76561b00569851819bf0952`。原包保留，解压到独立审核目录；没有替换现有review-r8数据、r7裁判、实验答卷或费用账本，也没有启动模型实验。

**结论**

F1.4可以作为统一课程来源的新基准候选。它实际处理了此前反馈的FIFO输入域、配方并发、部分歧义判分和时间单位问题，完整离线验收通过。但它尚未达到当前“真实CODESYS编译＋功能＋形式反馈”实验的接入条件：公共FIFO原接口参考ST在现有CODESYS环境报10个编译错误。应先解决这项平台兼容问题，再升级裁判和实验入口；不能只把旧题库目录换成F1.4后继续付费运行。

**这次变化比“补两条测试”大**

F1.4共946条功能记录，其中公共470条、自建476条；原实验review-r8为1214条，其中公共562条。数量减少有合并重复完整输入历史、移除越约或歧义扣分的原因，不等于测试退化，也不能仅凭数量认定更强。八道自建题合并前427个计分点、合并后265个，保留分叉轨迹所需前置过程，包内有逐条映射。

与实际运行的review-r8相比，接口签名变化有四题：

- public-easy-04：DebounceMs/CycleMs整数毫秒接口恢复为DebounceTime/CycleTime的TIME接口，累计输出恢复LTIME。
- public-hard-04：DINT数组＋capacity恢复VARIANT接口，容量由调用数组决定。
- public-medium-02：固定数组恢复ARRAY[*]开放数组，调用者下界和长度可不同。
- public-medium-06：LINT扫描计数恢复LTIME正常切割时间累计。

逐字段比对，9题需求文字、5题变量字段、27题规约列表和34题测试列表不同。列表差异包含分组格式、编号及标记，不能解释成34题全都改了题意；具体35题清单见`review_summary.json`。

更关键的是，20道公共题的首轮用户消息均与旧实验实际消息不同：F1.4直接发送教师原文，旧实验还包含本地适配、补充性质和检查清单。即使部分题的功能载荷相同，也不能把旧结果直接改名为“F1.4课程原文生成实验”。

鼓风机必须特别澄清：F1.3曾明确五次扫描；本次回到课程原文的五秒，并使用实际时间间隔。我们此前对五拍的讨论只适用于当时版本，不应继续套用到F1.4。

**已确认的接入阻塞：公共FIFO真实编译失败**

抽查平台为本项目已冻结的CODESYS V3.5 SP22 Patch 4（配置目录3.5.22.40），沿用原模板和编译入口，先运行正反控制。直接编译原包参考ST，没有把VARIANT改为DINT，没有增删接口。错误包括：

- `Unknown type: 'VARIANT'`（两处）
- `The operators LOWER_BOUND and UPPER_BOUND are only supported for arrays`
- `Cannot apply indexing with [] to an expression of type 'VARIANT'`
- 最终`Build complete -- 10 errors, 0 warnings : No download possible`

同一份FIFO参考程序在F1.4本地解释器功能测试31/31、受限调用方形式检查通过，并不等于其ST已经能在真实目标平台编译。这是执行环境与目标平台兼容性问题，不能在付费实验里把所有按原接口生成的代码都当作模型语法错误，再让模型反复修复。

应请队友提供保留原接口的目标平台实现、必需库和调用绑定方案，并给出真实编译证据；或者明确适用的平台及不能覆盖的范围。不能静默恢复旧DINT/capacity后仍称作课程原接口。详细反馈见[给队友的编译待修说明](给队友_F1.4编译待修说明.md)，原始结果见`native_spotchecks.json`。

**现有裁判也不能只换JSON**

新测试使用group（398条记录）、expected_any（4条）、scan_interval_ms（136条）。当前r7的TestCase定义没有这些字段，直接读取会丢掉分组、合理输出备选或真实时间信息。新程序还依赖TON、TIME/LTIME及开放数组绑定能力，不能以旧解释器静态解析大多数代码为“已兼容”依据。

F1.4的`task.py --candidate`结果包含用例期望与实际值，用于人工审核。接模型修复时应使用其脱敏反馈函数或等价过滤，不把整个评分JSON直接发给模型。本次已读到该函数明确排除期望/实际值和测试注释，但尚未接入或验证两框架的完整模型通道。

**建议采纳与后续顺序**

1. 将F1.4登记为候选统一来源，保留课程原文和原接口、给35题及首轮消息冻结指纹。旧review-r8和已完成140题次继续保留，不覆盖、不拼成同轮成绩。
2. 先解决FIFO真实编译和平台范围；在独立版本接入F1.4的分组、备选期望、真实时钟及绑定能力，保持费用和旧裁判现场。未决建模、参考轨迹判定和候选有界检查分开列。
3. 完成35题参考解在主目标CODESYS上的验收、相应错解控制，以及两模型×两框架的免费假响应通道。当前只抽查三题，不预先宣称全库可真实编译。
4. 再决定新增模型实验的范围与预算。若主张F1.4原文条件下的模型生成，应按冻结后的新条件采集，不能靠旧答卷改名。当前累计61.076553元，170元总上限和80元检查点不因来件版本变化而重置；新请求预留须重新精算。本轮审核不增加模型费用。

本次未采纳为活动题库、未更改主实验结果、未执行全量付费复测。机器可核对摘要为[review_summary.json](review_summary.json)，本机完整离线验收输出及CODESYS抽查结果随本说明归档。
