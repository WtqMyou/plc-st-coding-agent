## 2. 需要修改的问题（按严重度排序）

### P0-1 自建题数据停在 v1.2，复核修订未落进数据

**证据**（`agent_dev_r9_stage3/datasets/selfmade/` 实测）：

| `self-hard-05` | 13 用例 / 10 规约 | 25 / 15 | 扩非法复位、按住、边界、S2 改写等 10 条 |
| `self-hard-06` | 10 / 9 | 45 / 15 | 词面、边界、足迹、编码性质等 20+ 条 |
| `self-hard-07` | 13 / 7 | 40 / 9 | 积分步骤注释、切换当拍、复位四工况等 12 条 |
| `self-medium-05` | 11 / 8 | 25 / 9 | 闭区间边界、复位优先、量纲 kg/s 等 7 条 |
| `self-medium-06` | 10 / 6 | 18 / 9 | q1/q4 注释、bias 钳位、dt 边界、复位边沿等 9 条 |

v1.3 自建题已是 230 用例 / 106 规约（LTL 96 + 纯仿真 10）。**两轮结果不能混算**，
报告里必须写清"结果对应数据集版本 v1.2"。

**修改意见**：
1. 从我方 v1.3 交付包（`stbench_v1.3_*_完整工程.zip`）同步 `datasets/selfmade/`、
   `datasets/selfmade_new5.py`、`datasets/selfmade/tests/*.reference.st`、`datasets/selfmade/_index.json`；
2. 重跑 `python -X utf8 -m stbench.selfmade_refs`（应得 15/15 题 230/230 用例）与
   `scripts/check_dataset.py --selfmade`（15/15）作为入库闸门；
3. README 的"435 条用例"改为按版本标注：v1.2=435（301+134）、v1.3=531（301+230）。

### P0-2 `self-hard-03` 的 `fifo` 方向被静默改为 `inout`

**证据**：我方该题 `fifo` 为 `direction="input"`（`ARRAY[1..8] OF INT`）；队友副本为
`direction="inout"`，其余字段（provenance、specs 文本、9 条用例 tc_id）全等，**改动没有任何留痕**。

**影响**：`driver._run_case` 的 sequence 模式只从 `direction=="input"` 的变量读 `inputs`，
inout 必须走 `const_inputs`（我方 `docs/数据集规范.md` §9.2 事实 1 有实测记录）。
只改方向而不改用例通道，参考解/用例会在**新旧解释器上行为不一致**；这是"数据即契约"被破坏的典型。

**修改意见（二选一，必须显式）**：
- 方案 A（推荐，零成本）：恢复为 `input`，与我方 v1.3 冻结数据一致；
- 方案 B：保留 `inout`，但必须同步 (a) 参考解、(b) 全部用例的通道（`const_inputs`）、
  (c) `provenance` 里加一行"接口方向由 input 改为 inout 的原因"，(d) `docs/数据集规范.md` §9.1
  偏差表加一行，(e) 把 `_index.json`/`dataset_freeze` 的哈希重算。

### P1-1 五个新题 JSON 多了私有键 `mc_max_seconds`

**证据**：`self-hard-05/06/07`、`self-medium-05/06` 的 JSON 顶层多 `"mc_max_seconds": 60.0`；
我方 `stbench/schema.py` 不认这个字段（不是 `Problem` 的字段，`check_dataset` 不审计，
`driver.verify` 不消费）。

**影响**：私有键跨仓不通用；若别的解释器按"未知字段即错误"处理会直接拒收；
更糟的是别人以为它生效（其实被忽略），MC 超时行为与预期不符。

**修改意见**：把"单题 MC 超时"从数据里拿出来，交给实验配置/CLI 参数
（如 `run_experiment.py --mc-timeout`）；若坚持留在数据里，须在 `schema.py` 增字段、
`check_dataset.py` 加校验、文档写明单位与默认值。**不要只加键不改代码**。

### P1-2 生成器分叉（`datasets/selfmade_new5.py` 1111 行 diff）

**证据**：队友副本的 `selfmade_new5.py` 与我方 v1.3 生成器 diff 1111 行，缺：
- `main()` 里的 `selfmade_build.self_check` 自检钩子（自检不过不写盘）；
- 复核修订后的 5 题用例/规约/题面（q14–q25、S10–S15、边界用例等）；
- `refs` 模块导入改为"按文件位置找同目录"，不依赖 cwd。

**影响**：如果后续用队友的生成器重建数据，会把 v1.3 修订**整体覆盖**回 v1.2；
两个生成器并存＝没有单一真源，这是最容易被忽略的回归来源。

**修改意见**：只保留一份生成器（直接覆盖为我方 v1.3 版本），并约定
**"JSON 一律由生成器重建、禁止手改"**；加一条 CI/自检命令：
`python -X utf8 datasets/selfmade_new5.py && python -X utf8 scratch/export_references.py`
之后 `git diff --exit-code datasets/` 必须为空。

### P2-1 README 数字与仓库数据不一致

**证据**：README 写"R9 共 179 条 LTL、24 条仅由模拟测试覆盖"；实测三份副本数据为
**175 条 LTL、28 条纯仿真**（公共 96+18，自建 79+10）。
可能口径是运行期 `spec_policy/spec_observers` 追加了规约，但 README 没有说明。

**修改意见**：要么写清"179 = 入库 175 + 运行期追加 4"的依据文件与位置，
要么按入库数据更正为 175/28，并注明统计脚本。

### P2-2 三份完整副本并存，仓库 43 MB 且无 tag/release

**证据**：`agent_dev/` 25 MB、`agent_dev_r9/` 5.8 MB、`agent_dev_r9_stage3/` 6.3 MB，
每份都含完整 `stbench/` 包 + `datasets/` + `evidence/`；无 git tag、无 GitHub Release。

**影响**：换人接手时无法判断哪份是"当前真源"；重复文件与证据快照让 clone 变慢，
也容易在错误副本上改代码（三份中的 `stbench/` 已有细微差异）。

**修改意见**：`git tag r8/r9/stage3` 固化历史；主分支只保留**一份**当前源码树；
`evidence/` 移到 GitHub Release 或 `docs/` 下按版本归档，不进主树。

### P2-3 README 的"不含组员交接包"与事实不符

README 说"本仓库没有上传…其他组员交接压缩包"，但仓库内实际带有我方 v1.2 的
完整数据集副本（20 公共题 + 15 自建题 + 生成器 + 参考解 + docs）。
建议改为"包含成员 1 数据集 v1.2 的只读副本，以成员 1 交付包为准"，避免下一个人
误以为仓库里的数据是权威版本。
