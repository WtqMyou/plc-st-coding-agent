# V5剩余瓶颈与六题目标

本轮正式成绩保持原样。自研DeepSeek整题2/6、104/123用例；以下为免费诊断和后续建议，不是新实验成绩。

| 题目 | 当前功能用例 | 核实的问题 |
| --- | --- | --- |
| 果酱泵 | 20/20 | 功能通过；时间形式模型另列未决 |
| 滑动平均 | 21/21 | 功能通过；形式搜索截断另列 |
| 灌装 | 5/10 | 互斥阶段实现关闭了应保持的前序输出；首轮编译失败耗尽唯一修复机会 |
| 温控 | 36/37 | 冷却结束当拍恢复输出，但热计时器仍以此前锁定状态调用，直到下一拍才重启；第二次持续加热少计时间 |
| 配方 | 16/21 | 结构体赋值存在对象别名，清空查询结果会影响数据库对象；隔离值复制检查使同一代码达到19/21，余两项是同时命令处理 |
| IPv4 | 6/14 | 已生成实现的BYTE字符串访问从1开始，真实CODESYS为0基；其他组仍遇字符串下标类型被本地错误定为STRING等建模缺口 |

修复机会是实际限制：自研DeepSeek有3题首次原生编译失败，第二次候选分别成为灌装5/10、平均21/21、IPv4 6/14。只有一次修复时，编译失败的候选没有后续功能修复轮。

工程契约表目前主要作为模型注释记录，还没有把表里的保持/复位/优先级规则自动转成行为核对。配方的修复反馈还截去了状态轨迹前缀，导致关键的早期数据库变化不能完整回放。

其他已确认缺口：TO_LREAL未被本地解释器支持，使MiniMax平均题未决；本地字符串下标类型与真实CODESYS字节类型不同，使已通过原生编译的IPv4实现未决。上述结果不能都当成模型逻辑错误。

下一轮以自研DeepSeek六题功能6/6为目标：先在独立裁判版本修复值复制、字符串字节类型和转换支持，做真实平台控制与全库免费回归；再补齐可回放的完整反例和契约行为校验。建议增加到最多4候选，允许编译修复后再做功能修复，四组统一新规则、时间和预算，重新精算并冻结独立批次。

6/6是验收目标，不承诺某次随机生成一定达到。保持原题和期望值，不将开发者手改的答卷算成Agent自主成功。此阶段没有新增模型费用，没有修改旧题库、旧答卷、冻结裁判、历史成绩或账本。
