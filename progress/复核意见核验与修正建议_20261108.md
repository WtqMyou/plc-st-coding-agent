## 2. 对工程问题清单逐项判断

### P0-1：自建题仍使用旧版测试——成立，需升级并区分版本

实测三份冻结副本的原始 JSON 均为 35 题、435 条用例、203 条性质；公共题 301 条、自建题 134 条。新包为 35 题、531 条用例、220 条性质；公共题仍为 301 条、自建题 230 条。

### P0-2：FIFO 改成 inout 且没有留痕——方向差异成立，‘无留痕’不成立

当前 `self-hard-03/fifo` 为 `inout`，新包 JSON 为 `input`。但当前 `provenance.agent_dev_corrections` 明确记录 `input -> inout`，且 [R8 修订记录](../agent_dev/docs/修订记录.md) 已说明原因：调用方提供的队列存储需要原位写入。

新包参考解仍声明 `VAR_IN_OUT`。使用当前严格接口检查，确实得到 `E_INTERFACE`；功能用例全过不能消除接口不一致。该题原有 9 条用例没有任何一条把 `fifo` 放进 `inputs`、`const_inputs` 或 `init`，因此不能声称已复现“这些现有用例因通道变化产生差异”。

建议保留上游包的原始 `input` 和哈希作为来源；在新工作版本登记显式平台适配，统一为 `inout`，同时统一参考解、提示、接口闸门和调用方存储。新增用例若给 fifo 赋值，应使用已明确支持的通道；补充内容断言与平台验证，并重建索引/冻结清单。不要只把方向恢复为 `input` 而留下 `VAR_IN_OUT` 参考解。

### P1-1：mc_max_seconds 不被读取——不适用于当前实现

第三阶段 `stbench/schema.py` 已声明并反序列化 `mc_max_seconds`，默认 60 秒；`stbench/st/driver.py::_attach_model_check` 把它传入检查器 `max_seconds`。CLI 也有 `--mc-seconds`，实际实验还受统一配置和进程时限控制。因此不能把当前实验解释成“该字段被忽略”。

字段跨仓兼容性及审计不足值得采纳。新版本建议由实验配置明确控制检查预算，并登记覆盖顺序；如保留题目字段，应补正数、有限值及单位校验。两个框架使用同一限制，不把这项变更写成已经提升模型性能。

### P1-2：生成器分叉——版本管理风险成立，不宜整包覆盖

## 3. v1.3 仍需处理的具体问题

1. **FIFO 接口冲突。** 如上，JSON input 与参考解 VAR_IN_OUT 不一致，是当前可复现的入库阻断。
2. **PI 连续切换性质仍漏约束。** S7/S8 仍要求 `prev(normalMode)`。构造上一拍刚切换、本拍又切到串级的两拍快照，错误地改变 flowSP 和 valveCommand，包内全部 8 条 LTL 仍返回“此轨迹内未违反”。这不是参考解执行错误的证据，而是性质不足的具体证据；应去掉依赖上一拍正常运算的漏洞，同时明确首次拍、故障和复位的排除条件，并约束非串级切换时的阀位保持。
3. **PI 题面与用例相冲突。** 要求 4 写“任何模式切换当拍输出保持不变”，但 q11 从串级切自动时 flowSP 从 10.8 变成手动给定 10.0，只保持阀位。建议按既有实现拆开描述：切串级保持两输出；切自动/手动时 flowSP 采用手操给定、阀位当拍保持；下一拍手动可由操作员接管突变。工艺意见亦允许预置型接管，不必扩展成持续平滑控制。
4. **掩码性质过弱。** S13 用 `latchedCauseMask >= prev(latchedCauseMask)` 近似“历史位不丢失”。4→8 数值增大却丢失 bit2，仍能通过 S13。应以位集合包含关系或逐位性质表达历史保留，并另约束正确并入本拍线索。S14 的仿真覆盖仍需保留，不能把数值单调宣称为完整 OR 语义验证。
5. **模糊控制注释仍错。** q13 写 `5-20=-15` “在范围内、不触发钳位”，但实际期望是 power=0，必须改成“低于 0，触发下限钳位”；q4 有四条规则激活，其中一条输出为零，标题“三邻域同时激活”也应改准。原数值期望不需要因此修改。
6. **参数说明继续收敛。** PI 算法已经显式乘 dt，不宜再要求无条件做一次每周期换算；应完整说明增益量纲、离散计算和采样周期影响，避免双重折算。手动给定越界时是限制输入契约还是统一钳位，也需与输出恒在范围内的性质一致。这些决定先落题面和用例，再决定参考解是否需要改。
