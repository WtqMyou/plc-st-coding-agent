# 多泵均衡运行

队友来件有 14 条功能用例、6 条非空 LTL，包含独立初始化与组内连续两种执行方式。本版保留七题来件中的实际多泵参考 ST，并把多泵题扩展到 **19/19 条功能用例、9/9 条非空 LTL**。[基线复验](peer_baseline.json) · [功能评分](../evidence/full_run.json)

| 要求 | 公开输入或实际错误 |
|---|---|
| 严格超过 50 小时才允许轮换 | 工时差为 50 且收到轮换请求时仍应保持主泵；把比较写成 ≥50 的错解在第 2 拍被 S3 检出。 |
| 无请求保持原主泵 | 当工时差为 51 但 rotated=FALSE 时，主动换泵会违反队友已有的 S6。 |
| 正确选择主泵和备泵 | S7 检查达到换主条件后应选全场工时最短的泵，同工时选小泵号。S8/S9 分别约束备泵的重选和保持。 |
| 合法需求与较大的运行工时 | 首拍需求为 4，工时输入 [2147483648,20,30,40,50]，正确主泵为 2；用 DINT 存储首项后溢出的错解选了 1 号泵。 |

原预算显式检查因输入组合数量到限。保持声明的 8 拍和每拍 160 种输入，扩额后完成 76,960 条转移，全程未发现违反。另有 12 段定向错解轨迹核对阈值、平局、编号及备泵保持。[扩额证据](pump_wide_bounds.json) · [泵题定向输入](pump_requirements.json) · [宽工时反例](control_loop_audit.json)
