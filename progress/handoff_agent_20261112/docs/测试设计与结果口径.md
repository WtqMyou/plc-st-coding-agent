# 测试设计与结果口径

当前主实验为F1.4-P1：20道课程公共题、15道自建题；两模型DeepSeek/MiniMax，两生成通道自研/Codex CLI，共140题次。每题最多一次修复，实际执行235次请求，其中140次首轮、95次修复。

四组每组35题、946条功能用例，失败题保留在分母。原生CODESYS编译指标可评价34题；课程公共FIFO保持原VARIANT接口，平台限制单列，仍参加35题功能与形式评价。DINT开放数组变体作为独立工程证据。

| 指标 | 含义 |
| --- | --- |
| 完整代码 | 解析得到完整POU，独立于接口、原生编译和功能判定 |
| 原生编译通过 | 本轮真实CODESYS构建通过，不由解释器替代 |
| 功能整题通过 | 该题全部冻结功能用例通过 |
| 功能断言通过 | 逐用例累计，不能与整题通过率混写 |
| bounded_pass | 在该题声明的状态域、深度及预算内完成有界检查 |
| truncated | 触及声明的探索预算，按原状态保留 |
| inconclusive | 存在未决/未建模范围，按原状态保留 |
| violated | 记录了规约违反及相应反例 |
| not_run | 本轮未执行形式阶段，通常是之前的门控阶段未通过 |

主表的功能整题通过由36/140提升到56/140，新增20题，25.7%提升到40.0%；最终原生编译通过87/136；26份最终候选完成本轮有界检查通过。完整形式分类表和每个题次结果均提供原始数据。

自研与Codex合计功能通过均为28/70。在MiniMax配置上，自研13/35、Codex11/35，自研多通过2题。报告可表述“整体达到本次Codex基线水平，并在MiniMax配置上略有超越”。

两模型相同协议、参数、额度、裁判与修复规则冻结；按题轮换四组顺序。Codex使用真实CLI受控代码生成，外层统一提供反馈。首轮公共题文本与课程原文一致，参考代码和测试期望不进入模型提示。

原题库、提示、裁判、模型配置、顺序、工具身份和预算签名在运行前提交推送。每题次保存候选、实际请求、原响应、反馈及费用关联；实际编译结果还带独立nonce。本包提供所有正式题次及原始传输资料，便于逐项核对。
