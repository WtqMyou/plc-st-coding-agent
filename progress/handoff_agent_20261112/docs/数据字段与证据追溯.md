# 数据字段与证据追溯

每个正式题次唯一标识为`condition/pid`，例如`custom_deepseek-v4pro/public-medium-01`。`condition`由框架和模型组合，`pid`是冻结题号。

## 从汇总到原始记录

1. 在`04_数据与报告素材/逐题结果140.csv`找到题号和组别。
2. 打开`05_实验记录/最新正式实验/jobs/<condition>/<pid>.json`。
3. `attempts[0]`为首轮；存在`attempts[1]`时为唯一修复轮；`best_attempt`为冻结规则保留的候选。
4. 同目录的`.request_01/02.json`是实际发送的消息结构；`.response_01/02.json`保留原响应；`.candidate_01/02.st`保存提取ST；`.transport_01/02.json`为HTTP诊断。
5. `judge.cases`保存完整功能结果；`judge.model_check`保存形式状态、公式和反例；`feedback`为实际反馈文本。
6. `judge.platform_results.codesys`含真实编译状态、原始工程路径及源码指纹。交接包的`原生编译索引.json`将历史路径映射为包内路径。
7. 费用事件按`request.job_id`和`request.candidate_index`关联同一轮。`accounted_cny`是按冻结单价与用量结算的计入金额，原始token用量在metadata中。

## 所有关键字段

| 字段 | 说明 |
| --- | --- |
| `job_done` | 题次已正常归档 |
| `code_hash` | 保存候选源码的SHA256 |
| `functional_pass` | 功能整题通过标识 |
| `tests_passed/tests_total` | 该候选用例计数 |
| `native_pass` | 真实CODESYS编译是否通过 |
| `verification_status` | 形式阶段的独立分类 |
| `actual_model` | 上游实际回执模型身份 |
| `prompt_tokens/completion_tokens` | 实际回执token用量 |
| `credential_batch` | primary/secondary密钥子批次，明文密钥不在包内 |
| `execution_amendment` | 取消80元人工暂停的独立授权修订 |
| `study_plan_sha256` | 题次对应的冻结主计划指纹 |

`07_清单指纹/文件清单.json`覆盖整个交接包的文件路径、字节数和SHA256。Git来源版本在同目录来源信息中。包内所有原始工程、日志和答卷按原字节保留，说明、图表、表格是另行生成的交接材料。

历史实验在`01_原工程/progress/evidence`及原开发目录中完整保留。最新主实验以F1.4-P1的35题946用例为准，旧review-r8的1214用例成绩用于历史对照，不拼进本轮主表。
