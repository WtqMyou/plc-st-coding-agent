# 工程结构与模块说明

`01_原工程`保留原仓库结构。最新研究入口在`progress`，Agent可复用运行时在`agent_dev_r9_stage3/stbench`。R8、R9与中间复核版本一并保留，便于追溯演进过程。

## 主流程

任务需求与接口 → 同一模型下的自研直连或Codex CLI通道 → 静态/接口检查 → 真实CODESYS编译 → 功能扫描测试 → 有界形式检查 → 合格停止或携带反馈修复一次 → 归档。

四组采用相同题库、模型参数、裁判、修复机会和预算保护。Codex通道使用真实CLI与本地Responses网关，形成受控代码生成基线；裁判及反馈由外层统一提供。

## 可复用Agent内核

`agent_dev_r9_stage3/stbench/harness`保存Solver、运行记录、候选Attempt与反馈循环。`providers`定义模型响应接口；`transport`和`billing`负责身份校验、流式协议与费用预留结算；`st`保存解析、类型、执行语义。最新实验使用独立冻结控制器组合这些模块，原开发工程完整保留。

## 实现要点

- 功能测试支持single/sequence、分组独立状态、`expected_any`合法替代结果、`scan_interval_ms`实际扫描间隔。
- 原生编译从模板复制独立工程，逐次保存源程序、工程、诊断和nonce，不以解释器通过代替真实编译。
- 功能全过后再做有界形式检查，形成逐层推进的验证流程。
- 反馈提供编译诊断、失败用例标识/相关变量和规约违反信息；首轮与修复提示不提供参考答案和功能期望值。
- 至多首候选加一次修复，候选重复即停止；空正文/截断保留原响应，不自动补发。
- 费用在发送前预留，结算后记录用量；未知费用、身份异常、公共工具故障均留存现场。
- 所有候选、反馈、实际请求、响应、费用和版本签名可按题次关联。
