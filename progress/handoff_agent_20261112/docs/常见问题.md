**哪个是最新成绩？** F1.4-P1，35题、每组946用例，四组最终功能整题为15、17、13、11；图表和主表均使用这一轮。旧实验保留在原工程中作为演进资料。

**为什么140题次却有235次请求？** 140次首轮，95次使用了唯一一次反馈修复机会。

**自研达到了什么水平？** 本次自研合计28/70，与受控Codex基线28/70相同；MiniMax配置自研13/35对11/35略有超越。反馈后总体功能通过率从25.7%提升到40.0%，流程展现工程可行性。

**怎么展示真实运行而不重新花钱？** 用案例对照HTML及离线回放显示实际保存的候选、编译诊断、功能反馈和修复结果，再用`--verify`真实执行包内功能裁判。画面注明“真实实验记录回放/本地复验”。

**包内原工程为什么有E盘路径？** 它们是实验机配置和历史证据定位，保留原样供追溯。交接包默认回放与复验使用相对路径，不依赖这些E盘位置。

**没有CODESYS能做演示吗？** 可以查看完整日志和工程源码，运行Python功能复验。需要重新执行真实编译时，安装对应CODESYS平台并配置模板即可。

**是否需要新API密钥？** 查看、回放、绘图素材和离线核验都不需要。只有另开真实模型实验才需要独立凭据和新配置。

**报告如何引用形式检查？** 保留`bounded_pass/violated/truncated/inconclusive/not_run`分类；可以展示多泵案例从形式违反转为有界通过，说明形式反馈补充功能测试的价值。

**工业应用如何表述？** 助手已实现分层验证与反馈修复闭环，经过进一步调试、平台适配和工程验证，有望用于工业现场辅助编程、程序校验与调试。
