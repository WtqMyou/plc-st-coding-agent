## 2. 泵题两组都要计分：判分入口已修（这是本轮唯一的判分器改动）

你们担心的是对的——**旧入口会丢用例**：`stbench/harness/runner.py::_verify` 原来按 `problem.case_mode` 二选一调 `verify` 或 `verify_sequence`，而 `verify_sequence` 只跑 `mode == "sequence"` 的用例，`single` 组被整体丢弃**且不计入分母**，分数会虚高。

新增入口 `stbench/st/driver.py::verify_problem(src, problem, *, model_check=True)`：

- 按 `TestCase.group` 分组（`stbench/schema.py` 新增 `group: str = ""` 字段）；
- 组口径取该组第一条用例的 `mode`，空则回落 `problem.case_mode`；
- single 组每条用例一个全新实例；sequence 组 `replace(problem, test_cases=cases)` 后走 `verify_sequence`；
- **两组都计分**，分母是各组之和；单组且组名为空时直接转发现有实现，旧行为逐字节不变。

已改走它的调用方：`harness/runner.py::_verify`、`scripts/check_dataset.py::verify_ref`、`scripts/verify_one.py`、`scripts/mc_all.py`、`stbench/public_refs.py`、`stbench/selfmade_refs.py::run_all`、`scripts/dataset_stats.py`、`scratch/_rejudge.py`。

## 3. 形式化结论的强度：区分「给定轨迹成立」与「有界搜索成立」

这是你要求必须记录的一项。七道修订题的实测口径（`verify_problem` 输出，`mc_input_space` = 从用例取值推断的输入组合数，`depth` = 实际到达深度 / 题目名义深度）：

| 题 | 用例 | LTL | 输入组合 | 实际深度 / 名义 | traces | truncated |
|---|---|---|---|---|---|---|
| public-medium-04 | 20/20 | 5/5 | 27 | **8 / 8** | 13635 | False |
| self-hard-02 | 17/17 | 5/5 | 216 | 3 / 8 | 60000 | True |
| self-hard-04 | 14/14 | 6/6 | 84 | 3 / 8 | 29736 | True |
| self-hard-06 | 48/48 | 15/15 | 51200 | 2 / 8 | 60000 | True |
| self-hard-07 | 40/40 | 8/8 | 21600 | 2 / 8 | 60000 | True |
| self-medium-05 | 27/27 | 8/8 | 42336 | 2 / 8 | 60000 | True |
| self-medium-06 | 18/18 | 8/8 | 2400 | 2 / 8 | 60000 | True |

必须如实说明的三件事：

1. **只有 public-medium-04 是真正跑到名义深度 8 的**（组合 27，预算充裕）。其余六题都是 `truncated=True`，结论是「在**组合数 × 60 000 条轨迹预算**内未发现反例」，**不是**「已验证」。
2. **名义深度不等于实际深度**。`InputSpace.combos()` 是输入的**全笛卡尔积**，BFS 每次迁移耗一条 `mc_max_traces`。self-hard-06 有 8 个输入、组合 51200，第 1 层展开就吃掉 85% 预算，`depth` 停在 2。
3. self-hard-06 的 S10/S11 之所以**仍然有区分力**，是因为错解在**首拍**就违反（`currentCauseMask` 当拍就写错），不需要深搜；这一点在我们上面三个错解的实测里得到验证（都在 q48 与 S10 首拍被拒）。但你不要把它读成「深路径也验证过了」。

**我们已经量化并写进文档**：`stbench/docs/数据质量分析.md` 4.1 节「输入组合爆炸：名义深度与实际深度不是一回事」，含 6 题受影响清单（public-hard-02/05/06、self-hard-06/07、self-medium-05）与三种修法的取舍。

**修法（部分已落地）**：

- `Problem.from_dict` 现在真正读 `mc_max_depth` / `mc_max_traces` / `mc_inputs`（之前这三个键**根本没被读**，15 道自建题写了等于没写）；
- `_collect_domains` 现在消费 `mc_inputs`（显式收窄/补值，覆盖自动推断）；
- `StageResult` 新增 `mc_depth` / `mc_input_space`，报告可如实列出；
- `truncated` 诚实化：首拍就烧完预算时也置 True（public-hard-05 从 `trunc=False` 变 `trunc=True`，之前它会给出错误的乐观信号）。

**但 `mc_inputs` 默认不启用**：收窄等于声明「其余输入不影响被检查的性质」，需作者负责。self-hard-06 收窄到 4 个真正影响足迹的输入后组合从 51200 降到 64，`depth` 涨到 8、`trunc=False`，丢位变异体在 CE@2 被抓——这条已单独取证，但**没有**默认打开。

**另外一处判分器修复（也影响可比性）**：一条规约的原子命题引用候选里不存在的变量时，原来会把**整题的形式分清零**（`mc_specs_total=0`）。现在下沉到单条：只有那一条变 `inconclusive`，其余照常判定。实测 public-hard-02 参考解 `7 hold`；把内部变量 `phase` 改名后 `2 hold + 5 inconclusive`（改之前是 `0 hold / total=0`）。
